# Roadmap

各フェーズは独立して検証可能な単位とする。最大5フェーズ。

---

## Phase 1 — データ読み込みと基本構造

- CSV ファイルを pandas DataFrame として読み込む（MVP は CSV のみ）
- 列名・行数・データ型を標準出力に表示する
- 不正ファイル（存在しない、形式違い）に対するエラーメッセージを出す
- **検証基準:** サンプル CSV を渡して列一覧が正しく出力されること

## Phase 2 — 基本的なデータ品質チェック

- 列ごとの欠損率（%）を算出する
- 数値列に文字列が混在していないかデータ型の不整合を検出する
- 完全重複行およびキー列の重複を検出する
- 検出結果をコンソールに表示する（Markdown 出力はまだ不要）
- **検証基準:** 欠損・型不整合・重複を意図的に仕込んだテストデータで正しく検出されること

## Phase 3 — 前月比変化の検出

- 月次カラム（例: `2024-01`, `2024-02` ...）を自動認識する
- 隣接する月の変化率（%）を算出する
- 設定可能な閾値（例: ±20%）を超えた変化をフラグとして記録する
- **検証基準:** 変化率が閾値を超えた列が正しく抽出されること

## Phase 4 — Markdown レポート生成

- Phase 2・3 の検出結果を Jinja2 テンプレートで Markdown に整形する
- 下記ルール表に基づき、各問題項目の下に Power BI 改善コメントを自動付記する
- レポートをファイルに出力する（例: `report_YYYYMMDD.md`）
- **検証基準:** 出力 Markdown がそのまま読めるレポートになっていること

### Power BI 改善コメント生成ルール

| 検出内容 | 条件 | コメント方針 | Power BI 上の推奨アクション |
|---------|------|------------|--------------------------|
| 欠損が多い | 欠損率 20% 以上 | 空白表示や集計ズレの可能性を指摘 | フィルター・欠損補完・データソース確認 |
| 型が不一致 | 数値列に文字列が混在 | 集計エラーや可視化不具合の可能性を指摘 | Power Query で型変換を確認 |
| 重複行あり | 完全重複またはキー重複あり | 件数・売上などの二重集計リスクを指摘 | 重複削除またはキー設計を確認 |
| 前月比急変 | 変化率 ±20% 以上 | KPI 変動の確認を促す | データ更新日・集計条件・ソース変更を確認 |

## Phase 5 — CLI 仕上げと使いやすさ改善

- `typer` または `argparse` で CLI インターフェースを整える
- 閾値・出力パス・シート名などをオプション引数で指定できるようにする
- `--help` で使い方が確認できる
- `requirements.txt` と最低限の README を整備する
- **検証基準:** README の手順どおりに新規環境でセットアップして実行できること

## スコープ外（MVP）

- Excel (.xlsx) 対応（Phase 5 以降の任意拡張）
- 統計的異常値検出（IQR・Z スコアなど）
- Web UI
- Power BI への直接書き込み・API 連携
- 機械学習ベースの異常検出
- 複数ファイルの一括処理
