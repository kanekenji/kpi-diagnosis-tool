# Feature Spec: Phase 3 — 前月比変化の検出

## 前提

- Phase 1（`data_loader.py`）が返す `pd.DataFrame` を入力として受け取る。
- `month` は `YYYY-MM` 形式の文字列であること（Phase 2 のフォーマットチェック通過を前提とする）。
- `kpi_value` は数値として扱えること（Phase 2 の型整合性チェック通過を前提とする）。
- Phase 2 のチェックを通過していないデータを渡した場合の動作は保証しない。

---

## 1. 目的

`department + kpi_name` 単位で月次の `kpi_value` を時系列に並べ、隣接する月との変化率（前月比）を算出する。
変化率が **±20% 以上** のものを「急変」として検出し、標準出力に表示する。
Power BI 改善コメントの生成はまだ行わない（Phase 4 以降）。

---

## 2. 処理の定義

### ステップ 1 — month の昇順ソート

- `month` 列を文字列として `YYYY-MM` 形式のまま昇順ソートする。
- `YYYY-MM` 形式は辞書順ソートで時系列順になるため、日付型への変換は不要。
- ソートは `department + kpi_name` のグループ内で行う。

### ステップ 2 — グループ化と前月値の取得

- `department` + `kpi_name` でグループ化する。
- グループ内で `month` 昇順に並べた後、`kpi_value` の1行前の値（`shift(1)`）を `previous_value` とする。
- グループの先頭行（初月）は `previous_value` が存在しないため `NaN` になる。

### ステップ 3 — 前月比変化率の計算

計算式:

```
change_rate (%) = (current_value - previous_value) / previous_value × 100
```

**スキップ条件（変化率を計算しない場合）:**

| 条件 | 扱い | 出力メッセージ |
|------|------|--------------|
| 初月（`previous_value` が NaN） | 比較対象外 | `(初月のためスキップ)` |
| `previous_value` が 0 | ゼロ除算のためスキップ | `(前月値が 0 のためスキップ)` |
| `kpi_value`（当月）が NaN | 欠損のためスキップ | `(当月値が欠損のためスキップ)` |

### ステップ 4 — 急変の判定

- `|change_rate| >= 20.0` を「急変」とする。
- 閾値は固定値 `20.0` とする（Phase 5 で CLI 引数化予定）。

---

## 3. 出力内容

### 全件の変化率一覧

```
=== 前月比変化率一覧 ===

department    kpi_name  month    current  previous  change_rate  判定
-----------------------------------------------------------------------
営業部        売上高    2024-01  1200000       -         -        (初月のためスキップ)
営業部        売上高    2024-02   950000  1200000     -20.8%      急変 ⚠
営業部        売上高    2024-03  1350000   950000     +42.1%      急変 ⚠
営業部        成約件数  2024-01       42       -         -        (初月のためスキップ)
営業部        成約件数  2024-02       38      42       -9.5%      正常
...
```

### 急変サマリー

```
=== 急変サマリー（±20% 以上） ===

急変検出: N 件

  department   kpi_name  month    change_rate
  営業部       売上高    2024-02     -20.8%

```

急変が1件もない場合:

```

急変なし
```

---

## 4. 出力カラムの定義

| カラム名 | 内容 | 備考 |
|---------|------|------|
| `department` | 部署名 | グループキー |
| `kpi_name` | KPI名 | グループキー |
| `month` | 対象年月（`YYYY-MM`） | ソートキー |
| `current_value` | 当月の `kpi_value` | NaN の場合は空欄表示 |
| `previous_value` | 前月の `kpi_value` | 初月は `-` 表示 |
| `change_rate` | 前月比変化率（%） | スキップ時は理由を表示 |
| `判定` | `急変 ⚠` / `正常` / スキップ理由 | |

---

## 5. エッジケースの扱い

| ケース | 扱い |
|--------|------|
| 同一グループの月が1件しかない | 初月としてスキップ。急変には含めない。 |
| `previous_value` が `0` | ゼロ除算を回避し `(前月値が 0 のためスキップ)` と表示 |
| `kpi_value` が NaN（欠損） | `(当月値が欠損のためスキップ)` と表示 |
| 月が連続していない（例: 1月・3月でギャップあり） | データ上で隣接する行を「前月」として扱う。ギャップの検出はこのフェーズでは行わない。 |
| グループが存在しない（DataFrame が空） | Phase 1 の段階でデータ行なしエラーになっているため、このフェーズでは考慮不要 |

---

## 6. 成功条件

以下をすべて満たすとき、Phase 3 は完了とみなす。

- [ ] `department + kpi_name` 単位で前月比が計算され、一覧が出力される
- [ ] 変化率 ±20% 以上の行が「急変」として検出される
- [ ] 初月データが `(初月のためスキップ)` として扱われ、急変に含まれない
- [ ] `previous_value` が `0` の場合に計算エラーにならず、スキップ理由が表示される
- [ ] `kpi_value` が欠損の場合に計算エラーにならず、スキップ理由が表示される
- [ ] 急変が1件もない場合に「急変なし」と表示される
- [ ] 急変サマリーに件数と該当行（department・kpi_name・month・change_rate）が表示される

---
