# Feature Spec: Phase 4 — Markdown レポート生成

## 前提

- Phase 2（`data_quality.py`）が返すチェック結果を入力として受け取る。
- Phase 3（`monthly_change.py`）が返す前月比変化結果を入力として受け取る。
- レポート生成ロジックは Jinja2 テンプレートを使い、ロジックとテンプレートを分離する。
- LLM による自由文生成は行わない。コメントはすべてルールベースで出力する。

---

## 1. 目的

Phase 2・3 の検出結果を統合し、Power BI 改善コメント付きの Markdown レポートを `reports/` 配下に出力する。
レポートは追加加工なしにそのまま人に共有できる体裁とする。

---

## 2. 入力の定義

| 入力 | 型 | 取得元 |
|-----|----|--------|
| Phase 2 チェック結果 | dict（各チェックの結果構造体） | `data_quality.run_all_checks()` の戻り値に変更 |
| Phase 3 前月比結果 | `pd.DataFrame` | `monthly_change.compute_monthly_change()` の戻り値 |
| 元 CSV ファイル名 | str | スクリプト引数 |
| 実行日時 | datetime | レポート生成時に `datetime.now()` で取得 |
| 元 DataFrame の行数・列数 | int, int | Phase 1 の `load_csv()` 戻り値から取得 |

### Phase 2 チェック結果の構造

`run_all_checks()` を現在の「標準出力のみ」から「結果 dict を返す」形に変更する必要がある。
変更後の戻り値イメージ:

```python
{
    "missing": [
        {"column": "kpi_value", "count": 1, "rate": 10.0, "rows": [7]},
        ...
    ],
    "type_mismatch": [
        {"column": "kpi_value", "count": 1, "rows": [4], "values": ["千円"]},
        ...
    ],
    "month_format": [
        {"rows": [8], "values": ["2024/03"]},
        ...
    ],
    "updated_at_format": [
        {"rows": [3, 10], "values": ["20240131", "2024-1-31"]},
        ...
    ],
    "full_duplicates": {"count": 1, "rows": [11]},
    "key_duplicates": {"count": 2, "rows": [11, 12], "keys": [("2024-02", "営業部", "売上高"), ...]},
}
```

> この変更は既存の `scripts/check_quality.py` の出力に影響しないよう、
> `run_all_checks()` が結果 dict を返しつつ標準出力への表示も維持する設計とする。

## 3. 出力ファイル

| 項目 | 仕様 |
|------|------|
| 出力先ディレクトリ | `reports/`（存在しない場合は自動作成） |
| ファイル名 | `report_YYYYMMDD_HHMMSS.md`（例: `report_20240415_143022.md`） |
| 文字コード | UTF-8 |
| フォーマット | GitHub Flavored Markdown |

## 4. レポート構成とテンプレート仕様

### セクション 1 — レポート概要

```markdown
# KPI 診断レポート

- **対象ファイル:** sample_kpi.csv
- **実行日時:** 2024-04-15 14:30:22
- **行数:** 10 行 / **列数:** 6 列
- **総合判定:** ⚠ 問題あり（3 件）
```

**総合判定の定義:**

| 条件 | 表示 |
|------|------|
| Phase 2・3 の問題が 0 件 | `✅ 問題なし` |
| 問題が 1 件以上 | `⚠ 問題あり（N 件）` |

「問題」の件数は以下を合算する：
- Phase 2: 欠損ありの列数・型不整合件数・フォーマット不正件数・重複件数（完全 + キー）
- Phase 3: 急変件数

---

### セクション 2 — データ品質チェック結果

```markdown
## データ品質チェック結果

### 欠損チェック

| カラム | 欠損数 | 欠損率 | 行番号 |
|--------|--------|--------|--------|
| kpi_value | 1 | 10.0% | 7 |

> 💡 **Power BI 改善コメント:**
> `kpi_value` の欠損率は 10.0% です。Power BI ビジュアルで空白や集計ズレが生じる可能性があります。
> データソースの欠損補完、または Power Query でのフィルター設定を確認してください。

### 型整合性チェック

問題なし

### month フォーマットチェック

問題なし

### updated_at フォーマットチェック

問題なし

### 完全重複チェック

問題なし

### キー重複チェック

問題なし
```

---

### セクション 3 — 前月比急変チェック結果

```markdown
## 前月比急変チェック結果（閾値: ±20%）

急変検出: 2 件

| department | kpi_name | month | current | previous | change_rate |
|------------|----------|-------|---------|----------|-------------|
| 営業部 | 売上高 | 2024-02 | 950,000 | 1,200,000 | -20.8% |
| 営業部 | 売上高 | 2024-03 | 1,350,000 | 950,000 | +42.1% |

> 💡 **Power BI 改善コメント:**
> 上記 KPI で前月比 ±20% 以上の急変が検出されました。
> データの更新日・集計条件・データソースの変更がないかを確認してください。
```

急変なしの場合:

```markdown
## 前月比急変チェック結果（閾値: ±20%）

急変なし ✅
```

スキップ行がある場合は急変テーブルの下に追記する：

```markdown
**スキップされた行（計算対象外）:**

| department | kpi_name | month | 理由 |
|------------|----------|-------|------|
| マーケティング部 | リード獲得数 | 2024-03 | 前月値が欠損のためスキップ |
```

## 5. Power BI 改善コメントの生成ルール

コメントはルールテーブルに基づき機械的に出力する。1つの検出内容につき1ブロック。

| 検出内容 | トリガー条件 | コメント本文 | 推奨アクション |
|---------|------------|------------|--------------|
| 欠損が多い | 欠損率 ≥ 20% の列が 1 つ以上 | `{カラム名}` の欠損率は `{rate}%` です。Power BI ビジュアルで空白や集計ズレが生じる可能性があります。 | データソースの欠損補完、または Power Query でのフィルター設定を確認してください。 |
| 欠損あり（20% 未満） | 欠損数 ≥ 1 かつ欠損率 < 20% | `{カラム名}` に欠損が `{count}` 件あります。 | 欠損行がビジュアルに影響していないか確認してください。 |
| 型不一致 | 型不整合件数 ≥ 1 | `{カラム名}` に数値として扱えない値が混在しています。集計エラーや可視化不具合の原因になります。 | Power Query で列の型変換設定を確認してください。 |
| 重複行あり | 完全重複またはキー重複 ≥ 1 | 重複行が検出されました。件数・売上などの集計値が二重にカウントされるリスクがあります。 | 重複削除の処理、またはキー設計の見直しを検討してください。 |
| 前月比急変 | 変化率 ±20% 以上 ≥ 1 件 | 前月比 ±20% 以上の急変が `{N}` 件検出されました。KPI の急激な変動が含まれています。 | データ更新日・集計条件・データソースの変更を確認してください。 |
| 前月値欠損 | スキップ理由が「前月値が欠損のためスキップ」の行 ≥ 1 | 前月値が欠損しているため比較できなかった KPI があります。データの連続性が失われている可能性があります。 | データ更新漏れや抽出条件を確認してください。 |

**問題が何も検出されなかった場合のコメント:**

```markdown
> ✅ 検出された問題はありません。データ品質は良好です。
```

## 6. ファイル構成

新規作成するファイル:

| ファイル | 役割 |
|---------|------|
| `src/kpi_diagnosis/report_generator.py` | レポート生成ロジック（Jinja2 テンプレートへのデータ渡し・ファイル出力） |
| `src/kpi_diagnosis/templates/report.md.j2` | Jinja2 テンプレートファイル |
| `scripts/generate_report.py` | CSV を受け取り Phase 2・3 を実行してレポートを出力するエントリポイント |

変更が必要な既存ファイル:

| ファイル | 変更内容 |
|---------|---------|
| `src/kpi_diagnosis/data_quality.py` | `run_all_checks()` が結果 dict を返すように変更。標準出力への表示は維持する。 |

## 7. 成功条件

以下をすべて満たすとき、Phase 4 は完了とみなす。

- [ ] `reports/report_YYYYMMDD_HHMMSS.md` が生成される
- [ ] レポートに対象ファイル名・実行日時・行数・列数・総合判定が含まれる
- [ ] Phase 2 の全 6 チェックの結果がレポートに含まれる
- [ ] Phase 3 の急変一覧とスキップ行がレポートに含まれる
- [ ] Power BI 改善コメントがルール表に従って出力される
- [ ] 問題が検出されなかった項目に「問題なし」が明記される
- [ ] 全問題が 0 件のとき「✅ 問題なし」の総合判定が出力される
- [ ] 生成された Markdown をそのまま共有できる体裁になっている
