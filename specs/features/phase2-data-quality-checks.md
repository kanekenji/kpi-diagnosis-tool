# Feature Spec: Phase 2 — 基本的なデータ品質チェック

## 前提

- Phase 1（`data_loader.py`）が返す `pd.DataFrame` を入力として受け取る。
- ファイルの読み込みとバリデーション（必須カラム確認・文字コード確認）は Phase 1 の責務であり、このフェーズでは扱わない。

---

## 1. 目的

Phase 1 で読み込んだ DataFrame に対して、6種類のデータ品質チェックを実行し、問題の有無・件数・該当箇所を標準出力に表示する。
Power BI 改善コメントの生成はまだ行わない（Phase 4 以降）。

---

## 2. チェック項目の定義

### チェック 1 — 欠損数と欠損率

| 項目 | 仕様 |
|------|------|
| 対象カラム | 全カラム（6列すべて） |
| 算出内容 | 欠損数（絶対数）と欠損率（% = 欠損数 ÷ 行数 × 100） |
| 閾値 | Phase 2 では判定しない。数値を表示するだけ。 |
| 問題あり判定 | 欠損数 ≥ 1 の列を「問題あり」とする |

**出力例:**
```
[欠損チェック]
  month        : 欠損 0 件 (0.0%) → 問題なし
  department   : 欠損 0 件 (0.0%) → 問題なし
  kpi_name     : 欠損 0 件 (0.0%) → 問題なし
  kpi_value    : 欠損 1 件 (10.0%) → 問題あり  行番号: [6]
  target_value : 欠損 0 件 (0.0%) → 問題なし
  updated_at   : 欠損 0 件 (0.0%) → 問題なし
```

---

### チェック 2 — 数値カラムの型整合性

| 項目 | 仕様 |
|------|------|
| 対象カラム | `kpi_value`、`target_value` |
| 検出内容 | pandas が数値型（`int64` / `float64`）として読み込めなかった値、またはカラム全体が `object` 型になっている場合 |
| 判定方法 | `pd.to_numeric(..., errors='coerce')` で変換を試み、`NaN` になった行を「型不整合」とする |
| 問題あり判定 | 変換失敗行が 1 件以上ある場合 |

**出力例:**
```
[型整合性チェック]
  kpi_value    : 問題なし
  target_value : 型不整合 2 件 → 問題あり  行番号: [3, 8]  値: ['千円', 'N/A']
```

---

### チェック 3 — month カラムのフォーマット検証

| 項目 | 仕様 |
|------|------|
| 対象カラム | `month` |
| 期待フォーマット | `YYYY-MM`（例: `2024-01`） |
| 判定方法 | 正規表現 `^\d{4}-\d{2}$` にマッチしない行を「不正」とする |
| 欠損値の扱い | 欠損行はこのチェックでは対象外（チェック 1 で報告済みのため） |
| 問題あり判定 | 不正な値が 1 件以上ある場合 |

**出力例:**
```
[month フォーマットチェック]
  問題なし
```

```
[month フォーマットチェック]
  フォーマット不正 1 件 → 問題あり  行番号: [5]  値: ['2024/01']
```

---

### チェック 4 — updated_at カラムのフォーマット検証

| 項目 | 仕様 |
|------|------|
| 対象カラム | `updated_at` |
| 期待フォーマット | `YYYY-MM-DD`（例: `2024-01-31`） |
| 判定方法 | 正規表現 `^\d{4}-\d{2}-\d{2}$` にマッチしない行を「不正」とする |
| 欠損値の扱い | 欠損行はこのチェックでは対象外 |
| 問題あり判定 | 不正な値が 1 件以上ある場合 |

**出力例:**
```
[updated_at フォーマットチェック]
  フォーマット不正 2 件 → 問題あり  行番号: [2, 9]  値: ['20240131', '2024-1-31']
```

---

### チェック 5 — 完全重複行の検出

| 項目 | 仕様 |
|------|------|
| 対象 | 全カラムの値が完全に一致する行 |
| 判定方法 | `df.duplicated(keep='first')` で True になる行を重複とみなす |
| 問題あり判定 | 重複行が 1 件以上ある場合 |
| 出力内容 | 重複件数と重複行番号 |

**出力例:**
```
[完全重複チェック]
  問題なし
```

```
[完全重複チェック]
  完全重複 1 件 → 問題あり  行番号: [4]
```

---

### チェック 6 — キー重複の検出

| 項目 | 仕様 |
|------|------|
| キー定義 | `month` + `department` + `kpi_name` の組み合わせ |
| 判定方法 | 上記3カラムを subset に `df.duplicated(subset=[...], keep='first')` で True になる行を重複とみなす |
| 問題あり判定 | キー重複が 1 件以上ある場合 |
| 出力内容 | 重複件数・行番号・重複しているキーの値 |

**出力例:**
```
[キー重複チェック]  キー: month + department + kpi_name
  キー重複 1 件 → 問題あり  行番号: [7]  キー値: ('2024-02', '営業部', '売上高')
```

---

## 3. 出力の全体構造

```
=== データ品質チェック結果 ===

[欠損チェック]
  ...（各カラムの結果）

[型整合性チェック]
  ...

[month フォーマットチェック]
  ...

[updated_at フォーマットチェック]
  ...

[完全重複チェック]
  ...

[キー重複チェック]  キー: month + department + kpi_name
  ...

=== サマリー ===
チェック項目数: 6
問題あり: N 件
問題なし: M 件
```

---

## 4. 行番号の定義

- 行番号は **CSV のデータ行番号**（ヘッダーを 1 行目とした場合の 2 行目以降の番号）で表示する。
- 0-indexed ではなく 1-indexed で表示し、ユーザーがスプレッドシートで直接確認できるようにする。

---

## 5. エラー時の挙動

Phase 2 のチェック関数自体は入力 DataFrame が正常であることを前提とする。異常な入力は Phase 1 の段階で排除されている。

---

## 6. 成功条件

以下をすべて満たすとき、Phase 2 は完了とみなす。

- [ ] 欠損のある行の行番号と欠損率が表示される
- [ ] `kpi_value` / `target_value` に文字列が混在する場合、該当行番号と値が表示される
- [ ] `month` が `YYYY-MM` 形式でない場合、該当行番号と値が表示される
- [ ] `updated_at` が `YYYY-MM-DD` 形式でない場合、該当行番号と値が表示される
- [ ] 完全重複行が検出された場合、行番号が表示される
- [ ] `month + department + kpi_name` が重複している場合、行番号とキー値が表示される
- [ ] 問題がないチェック項目には「問題なし」と表示される
- [ ] サマリーに問題あり件数が表示される

## 8. 戻り値スキーマ

`run_all_checks()` は標準出力への表示に加え、以下の構造の `dict` を返す。
Phase 4 のレポート生成で再利用するために定義する。

```python
{
    "missing": {
        "status": "ok" | "warning",
        "count": int,           # 欠損のある列数
        "detail": [             # 問題ありの列のみ含む。なければ None
            {"column": str, "count": int, "rate": float, "rows": list[int]}
        ] | None
    },
    "type_mismatch": {
        "status": "ok" | "warning",
        "count": int,           # 型不整合の行数合計
        "detail": [
            {"column": str, "count": int, "rows": list[int], "bad_values": list[str]}
        ] | None
    },
    "month_format": {
        "status": "ok" | "warning",
        "count": int,           # フォーマット不正の行数
        "detail": [
            {"count": int, "rows": list[int], "bad_values": list[str]}
        ] | None
    },
    "updated_at_format": {
        "status": "ok" | "warning",
        "count": int,
        "detail": [
            {"count": int, "rows": list[int], "bad_values": list[str]}
        ] | None
    },
    "full_duplicates": {
        "status": "ok" | "warning",
        "count": int,           # 完全重複行数
        "detail": [
            {"count": int, "rows": list[int]}
        ] | None
    },
    "key_duplicates": {
        "status": "ok" | "warning",
        "count": int,           # キー重複行数
        "detail": [
            {"row": int, "key": list[str]}
        ] | None
    }
}
```

> **`bad_values` キー名について:**
> `type_mismatch` / `month_format` / `updated_at_format` の `detail` 内で検出された不正値リストのキー名は `"bad_values"` とする。
> Python / Jinja2 では `dict.values()` が組み込みメソッドとして存在するため、`"values"` をキー名に使うとテンプレートや辞書アクセスで意図しないメソッド参照が発生する。これを避けるために `"bad_values"` を採用する。
